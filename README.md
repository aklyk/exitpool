# exitpool

Локальные прокси-выходы для балансеров **3x-ui**: AmneziaWG (без Docker) и Happ Desktop (в Docker).
Каждый выход — socks-исходящий с TCP и UDP, со своей проверкой связи: если выход потерял связь, он
закрывается, и балансер панели уводит трафик на другие. Управление — командой `exitpool` (меню и команды),
по желанию — веб-интерфейс в домашней сети.

Бывший `happ-service`: установка 1.x переносится штатным обновлением, теги и порты для 3x-ui сохраняются.

## Что умеет

- **AWG-выход без Docker.** `amneziawg-go` в основном пространстве имён, интерфейс туннеля переносится в своё
  сетевое пространство `exitpool-ИМЯ`; там же реле Xray (socks, TCP и UDP) без привилегий.
  - Маршруты, DNS и firewall сервера не меняются.
  - Внутри пространства всё, что не идёт в туннель, отбрасывается (fail-closed).
  - Реле открывается только после проверки связи через туннель и закрывается через ~30 с после потери связи.
- **Happ-выход** (подписка `happ://crypt5/…`) — в Docker, как в 1.x.
- **Режимы памяти AWG-выхода** — у каждого выхода свой (таблица ниже).
- **Честная оценка памяти** перед установкой и перед каждым новым выходом.
- **Сканирование сервера**: подходит ли ядро (netns, veth, перенос TUN), есть ли nft и systemd с `NetworkNamespacePath`, свободны ли подсети и порты.
- **Бинарники AWG** — из релиза GitHub с проверкой SHA-256, через прокси (http, https, socks, с логином или без),
  из своей папки или сборкой из закреплённых исходников.
- **Связь с 3x-ui** по желанию: добавить исходящие через API и показывать, какой балансер выбрал выход.

## Требования

- Linux amd64 под systemd. Проверялась **Ubuntu 24.04**; на других системах решает сканирование.
- Для AWG: `/dev/net/tun` (на OpenVZ/LXC VPS его часто нет), `ip`, `nft`, `curl`, `setpriv`, `python3` 3.10+.
- Для Happ: Docker 28+ (мастер может поставить его из официального репозитория Docker) и ~1 ГБ диска под образ.

## Установка

```sh
sudo bash -c 'bash <(curl -fsSL https://gist.githubusercontent.com/aklyk/5d7c8f9eb430163320eb5fbce4b0fac8/raw/exitpool-install.sh)'
```

Опции пишутся после `)` внутри кавычек, например обновление:
`sudo bash -c 'bash <(curl -fsSL …/exitpool-install.sh) --upgrade'`. Если вы уже root (`sudo -i`) — просто
`bash <(curl -fsSL …/exitpool-install.sh)`. Вариант `sudo bash <(curl …)` **не работает**: sudo закрывает дескриптор,
через который bash читает скрипт (`/dev/fd/63: No such file or directory`).

Мастер покажет, что нашёл на сервере, предложит части с оценкой памяти, спросит профили AWG и режим памяти,
подписку Happ, веб и связь с 3x-ui, покажет итог и только после «да» начнёт. Подробности, прокси,
установка без доступа к GitHub — в [INSTALL.md](INSTALL.md).

## Режим памяти AWG-выхода

Выбирается для каждого выхода при добавлении, меняется позже (`exitpool set ИМЯ memory_mib=…`, меню или веб);
меняется с перезапуском только этого выхода. Выбор по умолчанию — 64.

| Режим | Что это значит | Оценка для бюджета | Жёсткие лимиты (выход / реле) |
|---|---|---|---|
| 32 МиБ | для экономии памяти: при нехватке процессора загрузки могут идти медленнее | ~80 МиБ | 128 / 64 МиБ |
| **64 МиБ** | рекомендуется: баланс памяти и нагрузки на процессор | ~100 МиБ | 128 / 96 МиБ |
| 128 МиБ | больше запаса памяти для интенсивной нагрузки | ~160 МиБ | 192 / 160 МиБ |
| своё | целое число от 32 | по той же шкале | по той же шкале |

Бюджет сервера: сумма оценок выходов + запас системе 128 МиБ (с Happ — 256 МиБ), от `MemAvailable`; swap не считается.
Happ-выход — ~256 МиБ, Docker (если его нет) — ~90 МиБ, веб — ~25 МиБ.

## Команда `exitpool`

`sudo exitpool` без аргументов — нумерованное меню. Команды:

```text
exitpool status [ИМЯ…] [--json]
exitpool add awg ИМЯ --profile ФАЙЛ|- [--memory 32|64|128|N] [--tag T] [--country FI] [--port P]
                    [--outbound veth|loopback] [--force-budget]
exitpool profile ИМЯ --file ФАЙЛ|-      заменить профиль AWG (если новый не заработал — вернётся прежний)
exitpool set ИМЯ memory_mib=32 mtu=1380 country=FI health_interval=10 failure_threshold=3 label=…
exitpool start|stop|restart|reconnect|probe ИМЯ   (restart --all — по одному, с проверкой каждого)
exitpool remove ИМЯ                      только AWG; профиль уходит в резервную копию
exitpool log ИМЯ [-n 80]
exitpool outbounds [--add]               JSON исходящих для 3x-ui или добавить через API
exitpool panel show|set|clear            связь с панелью для статуса балансеров
exitpool web show|enable|disable|passwd
exitpool access show|allow МОСТ ПОДСЕТЬ|deny МОСТ
exitpool proxy show|set|test|clear       прокси для скачиваний
exitpool binaries status|download|from-dir DIR|build
exitpool preflight [--awg 64 …] [--self-test]
exitpool subscription                    заменить подписку Happ
exitpool backups [--restore ID]
exitpool setup                           мастер: добавить AWG, Happ, веб
exitpool upgrade --from ПАПКА            (обычно — загрузчик с --upgrade)
exitpool cleanup-legacy                  убрать файлы happ-service после переноса
```

Секреты (профили, подписка, токен панели, пароли) принимаются только скрытым вводом, из файла или stdin и не печатаются.
Подробности ошибок с трассировкой: `EXITPOOL_DEBUG=1 sudo -E exitpool …`.

## Как подключить к 3x-ui

- AWG-выход: socks-исходящий `10.250.N.2:ПОРТ` (адрес и тег — в `exitpool status` и на карточке веба),
  UDP работает. Адрес доступен только с самого сервера: пересылаемый трафик к реле (контейнеры, другие машины)
  по умолчанию запрещён. Если 3x-ui работает в Docker не в сети хоста — `exitpool access allow <мост> <подсеть>`.
- Перенесённые из happ-service AWG-выходы сохраняют `127.0.0.1:ПОРТ` (TCP — через `systemd-socket-proxyd`, UDP —
  напрямую), поэтому панель менять не нужно. Перейти на veth: `exitpool set ИМЯ outbound=veth`, затем поменять адрес в панели.
- Happ-выход: `127.0.0.1:ПОРТ`, как раньше.
- Выходы добавляются в балансер отдельно. Для быстрого переключения — наблюдатель (`burstObservatory`) `10s × 2`;
  при `30s × 6` переключение медленное: реле закрывается за ~30 с, но панель может держать мёртвый выход ещё 1–2 минуты.

## Где что лежит

| Путь | Что |
|---|---|
| `/opt/exitpool` | программа, бинарники AWG (`bin/`), веб, файлы образа Happ |
| `/etc/exitpool` | настройки выходов, профили AWG (`awg/`, 0600), ключ подписки, панель, веб, доступ, прокси |
| `/var/lib/exitpool` | состояние и журнал событий выходов, резервные копии |
| `/run/exitpool` | временные файлы выходов (без ключей) |
| службы | `exitpool-awg@ИМЯ`, `exitpool-awg-relay@ИМЯ`, `exitpool-happ@ИМЯ`, `exitpool-web`, `exitpool-awg-guard` |

## Удаление

```sh
sudo bash /opt/exitpool/uninstall.sh [--purge [--all]]
```

Без опций — выходы и веб останавливаются, всё остальное остаётся. `--purge` убирает программу, службы и сетевые
объекты, ключи и настройки остаются; `--purge --all` удаляет и их. Исходящие в 3x-ui не трогаются.
