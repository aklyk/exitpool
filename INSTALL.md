# Установка и обновление exitpool

## Быстро

```sh
sudo bash -c 'bash <(curl -fsSL https://gist.githubusercontent.com/aklyk/5d7c8f9eb430163320eb5fbce4b0fac8/raw/exitpool-install.sh)'
```

- Опции — после `)` внутри кавычек: `sudo bash -c 'bash <(curl -fsSL …/exitpool-install.sh) --upgrade'`.
- Уже root (`sudo -i`): `bash <(curl -fsSL …/exitpool-install.sh) --upgrade`.
- `sudo bash <(curl …)` не работает: sudo закрывает дескриптор `/dev/fd/63`, через который bash читает скрипт.
- Через pipe тоже можно: `curl -fsSL …/exitpool-install.sh | sudo bash -s -- --upgrade` — мастер сам переключится на терминал.

Загрузчик из gist короткий, его можно прочитать целиком. Тот же файл есть в каждом релизе:
`https://github.com/aklyk/exitpool/releases/latest/download/exitpool-install.sh`. Он скачивает `exitpool-X.Y.Z.tar.gz` из релиза
GitHub, сверяет SHA-256 с записанным в нём значением, распаковывает архив во временную папку и запускает мастер.

Опции загрузчика (после `)` в команде выше):

| Опция | Что делает |
|---|---|
| `--upgrade` | обновить exitpool или перенести happ-service 1.x |
| `--add` | добавить к установленному exitpool AWG-выходы, Happ или веб (то же, что `sudo exitpool setup`) |
| `--plan` | только сканирование сервера и оценка памяти, ничего не меняется |
| `--proxy URL` | прокси для скачиваний (ниже) |
| `--version X.Y.Z` | другая версия; хеш берётся из `SHA256SUMS` этого релиза |
| `--from FILE` | архив, принесённый вручную (если с сервера GitHub недоступен) |
| `--binaries-dir DIR` | готовые `amneziawg-go`, `awg`, `xray` из папки вместо скачивания |
| `--build-binaries` | собрать бинарники AWG из исходников, не пытаясь скачать |
| `--force-budget` | продолжать, даже если памяти по оценке не хватает (на свой риск) |

Пример — обновление, когда GitHub доступен только через прокси (`-x` — для самого загрузчика, `--proxy` — для архива и бинарников):
`sudo bash -c 'bash <(curl -fsSL -x socks5h://127.0.0.1:1080 …/exitpool-install.sh) --upgrade --proxy socks5h://127.0.0.1:1080'`

Прокси с паролем лучше передать переменной (так пароль не попадёт в аргументы процессов):
`sudo EXITPOOL_PROXY='http://user:pass@host:3128' bash -c 'bash <(https_proxy=$EXITPOOL_PROXY curl -fsSL …/exitpool-install.sh)'`.

## Что спрашивает мастер

1. **Что нашёл на сервере**: система, память, Docker, TUN, 3x-ui, диск; проверки для AWG (инструменты,
   systemd, самотест ядра во временном netns — убирается сразу).
2. **Что поставить** — AWG-выходы, Happ-выходы, веб; итог по памяти пересчитывается при каждом переключении.
   Если не хватает — подскажет, что можно убрать или освободить, и сам ничего не меняет.
3. **Вопросы по выбранному.**
   - AWG: профиль `.conf` (путь к файлу или вставка скрытым вводом), имя, тег, страна, режим памяти (по умолчанию 64).
   - Happ: подписка (скрытый ввод), выбор профилей.
   - Веб: адрес LAN, подсеть клиентов, пароль.
   - 3x-ui: не связывать / добавить исходящие сейчас / добавить и показывать балансеры.
4. **Итог и «Начать?»** До этого момента на сервере ничего не меняется. Исключения: временные файлы,
   а для Happ — установка Docker (с отдельного согласия) и временный Happ, читающий подписку.

## Бинарники AWG

`amneziawg-go`, `awg` (статический, musl) и официальный `xray` для Ubuntu 24.04 amd64. Хеши закреплены в
`release/binaries.json`, исходники — в `release/versions.env`. Способы получить:

- **из релиза GitHub** (по умолчанию) — с проверкой SHA-256;
- **через прокси**, если GitHub с сервера недоступен:
  - если скачивание не удалось, мастер покажет настоящую ошибку curl и предложит варианты: повторить, прокси,
    сборка из исходников, папка с файлами;
- **из папки** (`--binaries-dir`, `exitpool binaries from-dir DIR`):
  - файлы, совпадающие с релизом, ставятся молча;
  - для своей сборки нужно отдельное подтверждение;
- **сборкой на сервере** (`--build-binaries`, `exitpool binaries build`):
  - нужно ~1 ГБ диска временно и несколько минут, доступ к github.com, go.dev и зеркалам Ubuntu;
  - пакеты компилятора ставятся на время сборки и после неё удаляются.

## Прокси для скачиваний

- **Типы:** `http://`, `https://` (TLS до самого прокси), `socks5h://` (имена разрешает прокси — рекомендуется), `socks5://`, `socks4a://`, `socks4://`.
- **Логин:** можно без него, можно в адресе (`http://user:pass@host:3128`) или отдельно — мастер спросит логин, пароль скрытым вводом.
- **Где взять:** если на сервере уже есть 3x-ui, подойдёт её локальный socks/http-вход: `socks5h://127.0.0.1:ПОРТ`.
- **Секреты:** пароль не печатается (`http://user:***@host`); curl читает его из временного файла 0600. Если передать пароль в `--proxy` загрузчика, он виден в `ps`, пока идёт установка, — безопаснее `sudo EXITPOOL_PROXY=URL bash …` или ввод в мастере (пароль скрытым вводом).
- **Хранение:** по умолчанию только на время установки. Мастер спросит, запомнить ли его для обновлений (`/etc/exitpool/proxy.json`, root 0600).
- **Управление:** `exitpool proxy show|set|test|clear`.
- **Пока не используется** для установки Docker и сборки образа Happ.

## Перенос с happ-service 1.x

```sh
sudo bash -c 'bash <(curl -fsSL …/exitpool-install.sh) --upgrade'
```

- **Что переносится:** ключ подписки, профили AWG, настройки панели и веба, история событий. Теги и порты прежние.
- **Порядок:** выходы переключаются по одному со старой службы на новую.
  - Если новая не заработала, возвращается старая и перенос останавливается; остальные выходы работают по-старому.
  - Повторный запуск с `--upgrade` продолжает прерванный перенос: уже перенесённые выходы не трогаются.
  - `cleanup-legacy` работает только после полностью завершённого переноса и при остановленных старых службах.
- **AWG-выходы** переезжают из Docker в режим без Docker:
  - режим памяти 64 МиБ;
  - адрес для 3x-ui остаётся `127.0.0.1:ПОРТ`, панель менять не нужно.
- **Happ-выходы:** тот же образ (переименовывается без пересборки, если исходники совпадают).
- **Старые файлы** happ-service остаются до `sudo exitpool cleanup-legacy`.
- **`happ_status.sh`** становится псевдонимом `exitpool status`.

## Обновление exitpool

`--upgrade` из загрузчика:

1. ставит новые файлы (копия прежних — в `/var/lib/exitpool/backups/*-upgrade`);
2. при смене версий бинарников скачивает новые;
3. предлагает перезапустить выходы по одному.

## Удаление

```sh
sudo bash /opt/exitpool/uninstall.sh            # остановить и отключить выходы и веб
sudo bash /opt/exitpool/uninstall.sh --purge    # убрать программу, службы, сетевые объекты; ключи остаются
sudo bash /opt/exitpool/uninstall.sh --purge --all   # и ключи, профили, подписку, настройки
```

- **Docker не трогается:** образ и сеть Happ остаются, команды для их удаления печатаются.
- **Вернуть после `--purge`:** загрузчик с `--upgrade` (или мастер без опций) найдёт сохранённые настройки и восстановит
  программу и службы с прежними профилями, ключами, портами и тегами.
- **3x-ui не трогается:** исходящие уберите из балансеров и удалите в панели сами.

## Если что-то не так

- `sudo exitpool preflight --self-test` — подходит ли сервер.
- `sudo exitpool status` — что с выходами.
- `sudo exitpool log ИМЯ` — журнал службы.
- `systemctl status exitpool-awg@ИМЯ exitpool-awg-relay@ИМЯ` — службы AWG-выхода.
